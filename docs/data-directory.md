# 数据目录说明

HDD Index 的发布包只包含程序文件，不包含用户的磁盘索引数据。升级或移动程序目录不会自动移动或删除数据。

## 默认配置位置

应用默认从以下位置读取配置：

```text
用户文档/HDD-Index/config.json
```

在 Windows 上通常对应：

```text
C:\Users\<用户名>\Documents\HDD-Index\config.json
```

配置中的 `JsonFilePath` 指向 Repository 和各磁盘 File Tree JSON 所在目录。这个目录可以位于用户文档目录，也可以位于其他本地磁盘。

## 首次启动

默认配置不存在时，应用会进入首次启动设置。选择一个数据文件夹后会创建：

1. 默认位置的 `config.json`
2. 所选数据目录中的 `RepoTreeData.json`
3. 名为 `Repository` 的空目录根节点

应用不会覆盖所选目录中已有的 `RepoTreeData.json`。如果该文件已经存在，请选择其他空目录；如果它本来就是要使用的旧数据，请退出并先恢复与它匹配的配置。

## 建议备份的内容

升级前建议同时备份：

1. `用户文档/HDD-Index/config.json`
2. `config.json` 中 `JsonFilePath` 指向的整个目录
3. 如果某个磁盘索引使用了其他独立路径，也一并备份对应 JSON

只备份程序安装目录不能保护索引数据，因为程序与数据默认分开保存。

## 更换电脑或用户账户

迁移时先复制配置文件和全部索引 JSON，再启动应用：

- 如果配置中的 `JsonFilePath` 已失效，启动窗口会显示原路径。选择包含 Repository 和磁盘索引的迁移后目录；应用先验证 Repository，成功后才写回配置。
- 如果某个索引对应的真实本地目录或盘符变化，在主界面选择该磁盘标签并点击“修复路径”，重新选择目录。该操作只修改 `LocalFolderPath`，不重新扫描索引。
- 如果只有一个磁盘索引 JSON 缺失、损坏或不可读，应用会隔离它并继续加载其他索引。警告会列出文件路径，本次会话不会覆盖被隔离文件。

配置或 Repository JSON 损坏时，应用只提供明确诊断，不会静默创建新文件覆盖旧数据。当前仍需从外部 Git 历史或手工备份恢复损坏文件。

## 保存安全边界

保存配置、Repository 或磁盘索引时，应用先在目标目录写入并刷新一个唯一临时文件，再原子替换原文件。单个写入失败不会把原 JSON 截断成半份内容。

这一保证只针对每个文件本身。一次操作如果依次保存多个 JSON，中途失败时已经保存成功的文件不会自动回滚；应用会保留整批未保存标记，修复故障后可以再次保存。外部 Git 仓库或备份仍然是版本回退手段。
